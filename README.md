# RAS — 위험성평가 시스템

공공하수처리장 위험성평가 업무용 대시보드. PC · 아이패드 · 아이폰 대응.

## 아키텍처

Worker 하나가 정적 SPA와 API를 함께 서비스한다(`worker/index.ts`, Hono).

```
브라우저(React SPA) ── /api/* ──▶ Worker ── D1(ras-db)    평가표·유해위험정보·설정(JSON)
                                        └── R2(ras-photos) 사진 원본
```

- **D1**: `assessments` / `hazard_infos` / `settings` 테이블에 프런트엔드 객체를 JSON 그대로 저장한다
  (`src/lib/types.ts`가 여전히 유일한 정본 스키마 — 서버는 재모델링하지 않는다)
- **R2**: 업로드 시 서버가 새 id를 발급해 저장하고(`POST /api/photos`), `<img src="/api/photos/:id">`로
  바로 불러온다. `photo_meta` 테이블에 크기·생성일만 별도로 남겨 저장소 화면 집계에 쓴다
- **로그인**: SSM 대시보드와 같은 방식 — 아이디·비밀번호(Worker 시크릿) + HMAC 서명 세션 쿠키.
  `worker/auth.ts`가 발급·검증하고, `/api/*`는 로그인·로그아웃 경로를 빼고 전부 이 세션을 요구한다
- 브라우저에는 더 이상 데이터가 남지 않는다 — 로그인하면 어느 기기에서도 같은 자료를 본다.
  `src/lib/localdb.ts`는 3단계 이전(IndexedDB) 시절의 흔적으로, 그 브라우저에 남은 옛 데이터를
  서버로 옮기는 마이그레이션 브리지 용도로만 쓴다(설정 → 백업·복원 화면에 자동으로 뜬다)

## 실행

```bash
npm install
npm run build            # worker가 서비스할 dist/ 를 미리 만들어 둔다
npm run db:migrate:local # 로컬 D1 스키마 적용 (최초 1회)
npm run dev:api          # Worker + D1 + R2 (포트 8788)
npm run dev              # Vite dev server — /api는 위 Worker로 프록시 (포트 5173)
```

두 명령을 각각 다른 터미널에서 띄워야 한다. `npm run dev`만 켜면 프런트는 HMR로 빠르게 도는데
`/api/*`가 8788로 프록시되므로 `dev:api`가 먼저 떠 있어야 정상 동작한다.

## 배포 (Cloudflare Workers)

```bash
npm run db:migrate   # 원격 D1 스키마 적용 (스키마를 바꿨을 때만 — 마이그레이션 파일을 순서대로 실행한다.
                     # 모든 DDL이 IF NOT EXISTS라 여러 번 돌려도 안전하다)
npm run deploy        # build + wrangler deploy
```

첫 배포 전에 D1 데이터베이스와 R2 버킷을 한 번 만들어야 한다(이미 만들어져 있고 `wrangler.toml`에
바인딩돼 있음 — 새 환경에 옮길 때만 다시 필요):

```bash
npx wrangler d1 create ras-db        # → database_id를 wrangler.toml에 반영
npx wrangler r2 bucket create ras-photos
npm run db:migrate
```

배포 주소: https://ras.hubfib.workers.dev · 저장소: https://github.com/ronn94/RAS

## 확정 사양

- 위험성 = 가능성(1~5) × 중대성(1~4), **8점 이상 = 고위험군**
- 평가코드 `YY.공정순-일련번호` — 8점 이상 행에만 자동 부여(수동 수정 가능)
- 개선 후 8점 미만이 되어도 고위험군 목록에 남고 `개선완료` 상태로 표시
- 사진은 개선 전/후 각 1장, 업로드 시 최대 1600px · JPEG 80%로 자동 축소
- 출력은 브라우저 인쇄 — **사방 여백 15mm**, 페이지를 억지로 채우지 않는다
  - 감소대책 사진대지: A4 세로 · 1페이지 2건 / 유해·위험 정보: A4 가로 1장
  - 대시보드 보고서는 두 종류다 — **회의자료용 상세**(`DashboardSheet`)와 **월간 게시용**(`MonthlyReportSheet`).
    둘 다 렌더해 두고 CSS로 감출 수 없다(`.print-root`의 `display:block !important`가 `.no-print`를
    이겨 버린다) — 그래서 고른 한 종류만 DOM에 둔다(`Dashboard.tsx`의 `sheet` 상태)
  - 위험성 평가표: A4 가로, 페이지마다 대상시설·공정명·결재란 머리말을 통째로 반복한다
    (`src/print/AssessmentSheet.tsx`) — 페이지 수만큼 완전히 독립된 표를 각각 그린다
  - **페이지를 나누는 기준은 행 개수가 아니라 실제 높이다.** 행 높이는 내용 줄바꿈에 따라 11mm~40mm+로
    달라지므로 고정 행수로 자르면 묶음이 한 장을 넘쳐 브라우저가 페이지를 강제로 쪼갠다. 그러면
    ① 잘린 조각에 머리말 표가 안 찍히고 ② Chrome이 조각의 세로 테두리를 누락시킨다.
    그래서 화면 밖에서 전체 행을 한 번 렌더해 높이를 재고(`useLayoutEffect`) 그 값으로 나눈다
  - **표 테두리는 `border-collapse: collapse`가 아니라 `separate`**로 그린다(셀은 오른쪽·아래,
    표는 위·왼쪽 담당). collapse는 페이지 경계에서 쪼개진 조각의 세로선이 통째로 사라지는
    Chrome 버그가 있다 — 실제로 재현·확인한 문제다
  - 첨부 사진은 비율과 무관하게 모두 70×47mm로 통일(`object-fit: cover`, 중앙 기준으로 가장자리를 잘라냄)
  - 위험내용·개선내용만 줄바꿈하고 나머지 텍스트는 칸 너비에 맞춰 최대 50%까지 자동 축소(`src/print/FitText.tsx`)
  - 인쇄 서식은 화면 밖(`left:-20000px`)에 렌더된다 — 폭 측정을 위해 `display:none`을 쓸 수 없다
- 위험성평가표 화면에는 결재란이 없다. **엑셀 내보내기는 화면 표의 모든 컬럼**(개선일자·조치상태·담당자 포함, 결재란 제외)을 담는다
- **개선예정일**(계획)과 **개선일자**(실제 완료일)는 서로 다른 필드다. 개선일자는 고위험군 관리 팝업과
  위험성평가 목록 표(개선예정일 바로 뒤)에서 같은 값을 공유한다 — 어느 화면에서 고쳐도 같이 바뀐다
- **월간 게시용 보고서**(`src/print/MonthlyReportSheet.tsx`)는 매월 말일에 뽑아 사무실에 게시한다
  - 위 65%(174mm): 제목(대상 월 자동, 오른쪽 끝에 작은 회색 쪽수) · 지표표 · 개선 전/후 히트맵(전체
    누적, 흑백 농도) · 그달 개선 완료 내역
  - 아래 35%(93mm): **열람 명단** — `번호·이름·서명` 3세트 가로 배치, 기본 24칸. 직원이 손으로 서명한다
  - 두 구역의 높이를 mm로 못박아 **서명표 자리가 매달 같다**. 내역이 3건이든 20건이든 레이아웃이 안 흔들린다
  - **개선 완료 내역은 줄바꿈을 잘라내지 않는다** — 유해위험요인·개선내용이 길면 그만큼 행이 커진다.
    그래서 "페이지당 몇 건"을 고정하지 않고, `AssessmentSheet.tsx`와 같은 **2단계 측정 방식**으로 나눈다
    (`MonthlyReportSheet` 컴포넌트 본문): 1단계로 전체 내역을 한 페이지에 몰아 화면 밖에 그려 각 행의
    실제 높이를 재고, 2단계로 그 높이만큼씩 페이지에 채워 넣는다(넘치면 다음 페이지로). 페이지가
    여러 장이면 머리글 오른쪽에 `2 / 3페이지`를 작게·회색으로 붙인다. 폰트 크기는 어떤 경우에도
    줄이지 않는다 — 유난히 긴 항목 하나가 그 페이지 남은 공간을 넘기면 그 페이지만 예정보다 적은
    건수로 끝나거나(정상 케이스), 극단적으로 항목 하나가 267mm를 넘기면 그 페이지 자체가 길어진다
    (`.top`의 `overflow: visible` — 잘라내는 것보다 낫다는 판단)
  - 유해위험요인·개선내용·비고는 **폭을 남는 공간에서 나눠 갖는다**(균등 27.7mm → 33.2/33.2/16.6mm,
    비고가 여백이 많이 남아 40% 줄이고 그만큼을 유해위험요인·개선내용에 절반씩 더 줬다). 긴 텍스트는
    `<td>`가 아니라 안쪽 `<span className="wrap">`에 줄바꿈을 건다 — `<td>`에 직접 걸면(예:
    `display:-webkit-box`) 표 레이아웃이 깨지면서 행 높이가 실제 내용과 무관하게 널뛴다(실제로 겪은 문제)
  - "그달 내역"의 기준은 **개선일자(`improveDate`)가 그 달인 행**이다. `RiskItem`에는 행 단위 수정시각이
    없어서 "수정된 행"은 판별할 수 없다 — 그래서 실제 개선 완료일을 기준으로 삼는다
  - 지표표의 개선 완료율은 **개선일자 기준**(`completionRateByDate`)이다. 대시보드 화면 카드는 여전히
    조치상태 기준(`completionRateAll`)이라 숫자가 다를 수 있다 — 의도된 차이다
  - 열람 명단은 설정 → **직원 명단**(`settings.staff`, 담당자 목록과 별개)에서 관리하고 인쇄 때
    이름 가나다순(`localeCompare("ko")`)으로 정렬된다. 명단이 24명보다 적으면 빈 칸을 채워 표 크기를
    고정하고, 24명을 넘으면 행 높이를 최소 5mm까지 줄여 한 장을 지킨다
  - 대상 월은 대시보드의 드롭다운에서 고른다(개선일자가 있는 달 + 당월, 최신순)
- **유해위험요인 분류표**(`HAZARD_FACTORS` in `src/lib/types.ts`)가 위험분류의 정본이다 —
  원본 서식 `SSI-602-06` 양식4-1에서 가져온 요인구분 7개와 유해위험유형 코드 35개 + 추가분 1개(`7.3 교통안전`)다.
  7.3은 원본 서식에 없다 — 출퇴근 교통재해 항목이 12건이나 돼 전부 `7.2 기타사항`으로 뭉치면
  집계가 무의미해져서 따로 뒀다
  - **요인구분 이름이 곧 위험분류**다. 예전에는 위험분류가 문자열 배열(`settings.hazardClasses`)이었는데
    설정의 `hazardFactors`로 바뀌었다. 이름은 원본의 "기계적 요인"이 아니라 기존 데이터와 같은 "기계적"을 쓴다
  - 예전에 따로 있던 `화재·폭발`·`밀폐공간`은 원본 서식에서 **코드로 흡수**돼 있다(화재=3.8, 폭발/파열=3.9는
    화학적 아래, 질식위험·산소결핍=5.1은 작업특성 아래). 다만 이미 그 값을 쓰는 행이 있을 수 있어
    `withDefaults`의 `migrateFactors()`가 옛 `hazardClasses` 중 분류표에 없는 이름을 **코드 없는 요인구분으로
    살려 둔다** — 그래서 예전 설정을 쓰던 브라우저도 값이 사라지지 않는다
  - 평가표 상세의 **위험코드**(`RiskItem.hazardCode`) 드롭다운은 고른 위험분류에 속한 유형만 보여준다.
    목록에는 `1.4 부딪힘`처럼 번호+이름을 띄우고 **저장되는 값은 번호(`1.4`)뿐**이다(`typesOf`/`codeLabel`)
  - **위험분류를 바꾸면 위험코드는 자동으로 비운다** — 분류에 속하지 않는 코드가 남으면 안 되기 때문
  - 번호·이름 모두 설정에서 고칠 수 있고, '기본 분류표로 되돌리기'로 기본값을 되돌린다.
    분류를 목록에서 빼도 이미 입력된 값은 남는다(공정명·조치상태와 같은 규칙)
  - 반영 범위: 평가표 상세 표 · 엑셀 내보내기/가져오기(`위험코드` 열, 총 19열) · A4 위험성평가표 인쇄물
    (위험분류 칸에 두 줄로) · 고위험군 목록(분류 배지 아래 작게) · 월간 게시용 보고서(**평가코드 열을 대체**, 번호만)
- **순회점검 조사표**(`src/pages/Inspections.tsx` · `src/print/InspectionSheet.tsx`)는 원본 서식
  `SSI-602-06` 양식4를 재현한다. D1 `inspections` 테이블(마이그레이션 `0002`)에 JSON으로 담는다 —
  평가표·유해위험정보와 같은 방식이라 워커의 `collection()` 제네릭을 그대로 쓴다
  - `유해위험 유형` 칸은 분류표 **전체 코드를 한 드롭다운에 편다**(`HazardTypeSelect` · `allTypes()`) —
    원본 서식에 위험분류 열이 없어서다. 표시 규칙은 평가표의 위험코드와 같다(목록은 `1.4 부딪힘`, 칸은 `1.4`)
  - **발굴 항목을 위험성평가표로 옮길 수 있다** — 내용은 `유해위험요인`, 유형은 `위험코드`와
    거기서 역산한 `위험분류`(`classOfCode()`), `비고`에는 `순회점검`이 들어간다. 옮긴 항목은
    순회점검에 그대로 남고 `이관됨` 배지가 붙으며 체크박스가 잠겨 **중복 전송이 막힌다**
  - **`이관됨` 배지는 저장된 표시가 아니라 파생값이다**(`inspectionMoved()`) — 이관할 때 만든
    평가표 행의 id를 `movedTo.rowId`에 남기고, 그 행이 아직 있는지를 그릴 때마다 확인한다.
    그래서 평가표에서 그 행을 지우면 배지가 저절로 풀리고 다시 이관할 수 있다(상태 동기화가 없어
    어긋날 일이 없다). 어느 평가표에 있는지는 보지 않고 **행 id만** 찾는다 — 평가표 상세의
    '다른 평가표로 이동'은 행 id를 그대로 두므로, 옮겼다고 배지가 잘못 풀리면 안 되기 때문이다
  - 참석자는 설정의 **직원 명단**에서 고르고 소속은 설정의 **기본 소속**(`org.dept`, 초깃값
    `용인사업소`)이 미리 채워진다. 서명은 인쇄 후 수기다
  - 새 순회점검은 발굴 1행·참석자 1행으로 시작한다(원본 서식의 14행/10명은 **인쇄할 때만** 채운다)
  - 인쇄는 세 가지(조사표 / 사진대지 1X2 / 2X2)라 **고른 한 종류만 DOM에 둔다** — 전부 렌더해 두면
    한꺼번에 찍힌다(`.print-root`의 `display:block !important`가 `.no-print`를 이긴다)
  - 조사표는 원본대로 발굴 **14행**·참석자 **5행 × 2세트**를 최소로 채운다. 그보다 많으면 늘어난다
  - **순회점검 사진도 고아 사진 정리(`cleanupOrphanPhotos`)와 백업에서 반드시 세야 한다** —
    빠뜨리면 정리할 때 통째로 지워진다
- **의견청취 설문지**(`src/pages/Surveys.tsx`)는 근로자가 직접 위험요인을 제출하는 서식이다.
  D1 `surveys` 테이블(마이그레이션 `0003`)에 JSON으로 담고, 한 장에 의견 한 건을 적는다
  - **게스트 권한 `survey`를 새로 뒀다.** 기존 `edit` 하나로는 설문지만 열어 줄 방법이 없었다 —
    그걸 켜면 평가표·유해위험정보·순회점검까지 전부 편집됐다. `requirePermission()`이 여러 키를
    받아 **하나라도 켜져 있으면 통과**하도록 바꾸고, `collection()`에 필요한 권한을 주입한다
  - 사진 업로드(`POST /api/photos`)는 `photo` **또는** `survey`면 통과한다. 업로드만으로는 아무 데도
    못 붙이고(붙이려면 그 화면의 쓰기 권한이 필요) 설문지에 사진을 넣으려면 열어야 하기 때문이다
  - **워커도 프런트와 같은 기본값을 쓴다**(`loadPermissions()`가 `DEFAULT_SETTINGS.permissions`를
    깔고 저장값을 덮어씀). 안 그러면 권한 키를 새로 추가할 때 프런트는 기본값을 보고 버튼을 열어
    주는데 서버는 `undefined`를 보고 403을 내는 불일치가 생긴다(실제로 겪은 문제)
  - **평가표 이관은 관리자(편집 권한) 몫이다** — 이관은 공식 평가표를 고치는 행위라 게스트에게
    열지 않는다. 근로자는 의견을 내고, 반영 여부는 관리자가 검토해서 정한다. 서버도 평가표 쓰기를
    `edit`으로 막으므로 UI를 열어 봐야 403이 난다
  - 위험성(가능성 × 중대성)은 입력칸이 아니라 **자동 계산**해 배지로 보여준다
  - **자동 저장하지 않는다.** 다른 화면과 달리 `+`를 눌러도 서버에 아무것도 안 남고, 화면에서만
    들고 있다가(`SurveysPage`의 `draft` 상태) **`제출`을 눌러야 등록**된다. 사진을 뺀 모든 항목이
    채워져야 버튼이 열리고, 안 채운 항목은 버튼 옆에 이름으로 보여준다. 제출하면 목록으로 돌아가
    등록된 것을 바로 확인한다. 이미 등록된 설문지를 열면 버튼이 `저장`으로 바뀌며 검증은 같다
  - 이관·인쇄는 **제출한 뒤에만** 할 수 있다(아직 서버에 없는 설문지는 대상이 아니다)
  - 인쇄물은 위 60%가 입력 내용, **아래 40%(107mm)가 근로자 FEEDBACK**이다(원본 `SSI-602-09(3)`) —
    평가항목 4구분 × 4단계 체크표 · 차후 개선 의견 · 종합 의견 · 평가일시 · 평가자 · 서명란.
    전부 인쇄 후 손으로 적는 칸이라 **화면에는 입력창을 두지 않는다**. FEEDBACK 자리를 확보하려고
    사진 칸을 62mm→46mm, 서술 칸을 26mm→23mm로 줄였다(합계 264mm로 A4 한 장에 들어간다)
  - 이관 시 세부공정·위험분류·위험코드·유해위험요인·가능성·중대성·개선대책·개선예정일이 그대로
    들어가고 비고에 `의견청취 · 작성자`가 남는다. `이관됨` 판정은 순회점검과 같은
    `inspectionMoved()`를 쓴다 — 평가표에서 그 행을 지우면 배지가 저절로 풀린다
- 위험성평가 목록의 "개선완료"는 상태값이 아니라 **비율**이다 — 분모는 해당 공정의 전체 등록 건수,
  분자는 **개선일자가 입력된 건수**(실제 개선 완료). 목록은 공정순번 오름차순으로 나열된다.
  대상시설~개선완료 6칸은 **폭을 균등하게 나눈다**(`table-fixed` + `calc((100%-9rem)/6)`) — 양끝
  공정순번·삭제 버튼만 고정폭이고, 좁은 화면에서는 표에 건 `min-w-[56rem]`이 가로 스크롤로 넘긴다
- 평가표 상세 표에서 조치상태가 **미조치**인 행은 붉은 배경으로 구분한다
- 대시보드 지표는 **전체 항목 기준**이다 — 전체 집계건수와 전체 개선 완료율을 큰 숫자로 두고,
  고위험군 건수·완료율은 그 아래 작은 글씨로 함께 보여준다(완료 판정은 조치상태 "개선완료" 기준)
- 평가표 상세 표의 행은 다른 평가표로 옮길 수 있다(이동 아이콘, 삭제 왼쪽) — 옮기면 평가코드는
  대상 평가표 기준으로 다시 매겨진다
- 화면의 도구 버튼(엑셀·인쇄·PDF·추가·백업)은 아이콘만 표시한다. 확인 다이얼로그의 취소/삭제 버튼은 글자를 유지한다
- 데이터는 Cloudflare D1(자료) + R2(사진)에 저장된다. 설정 → 백업·복원에서 JSON 백업·복원(병합)

## 로그인 (아이디·비밀번호 + 게스트)

SSM 대시보드와 같은 방식 — 계정을 여러 개 두지 않고, 안전팀이 공유하는 관리자 계정 하나를 쓴다.
`worker/auth.ts`가 HMAC로 서명한 세션 쿠키(HttpOnly·Secure·SameSite=Strict, 12시간 만료)를 발급하고,
비밀번호 자체는 어디에도 저장하지 않고 매 요청마다 시간 상수 비교(`timingSafeEqual`)만 한다.
`/api/*`는 로그인·로그아웃·게스트 로그인 세 경로를 빼고 전부 이 세션이 있어야 통과한다(`worker/index.ts`).

계정 정보는 코드·저장소에 없고 Worker 시크릿으로만 존재한다. 바꾸려면:

```bash
printf "새아이디" | npx wrangler secret put ADMIN_USERNAME
printf "새비밀번호" | npx wrangler secret put ADMIN_PASSWORD
```

로컬 개발은 `.dev.vars`(gitignore됨)에 `ADMIN_USERNAME`·`ADMIN_PASSWORD`·`SESSION_SECRET`을 넣어 쓴다.

### 게스트 (뷰어 계정)

로그인 화면의 &lsquo;게스트로 보기&rsquo;는 비밀번호 없이 `sub: "guest"` 세션을 받는다. 게스트는:

- **설정·백업/복원 화면 자체가 사이드바에서 사라진다** (`Shell`의 `hiddenViews`), 상태를 직접 조작해도
  `App.tsx`가 한 번 더 막는다
- **관리 API는 서버가 무조건 차단**한다(`adminOnly` 미들웨어) — 설정 변경, 백업 내려받기·복원, 전체 초기화,
  저장소 사용량, 사진 정리는 권한을 아무리 켜도 게스트에게 절대 열리지 않는다
- **편집·삭제·사진 첨부는 설정에서 개별로 켤 수 있다** — 설정 → 게스트 권한 카드에서 토글하면
  `AppSettings.permissions`(D1에 저장)에 반영되고, `requirePermission()` 미들웨어가 매 요청마다
  최신 값을 읽어 검사한다. 꺼져 있으면 서버가 403을 준다(프런트는 버튼을 `disabled`로 미리 흐리게 표시)
- 화면 조회·엑셀 내보내기·PDF 인쇄는 게스트에게도 항상 열려 있다 — 서버에 아무것도 쓰지 않는 읽기 동작이라서다

프런트엔드 가드는 `useStore()`의 `canEdit`/`canDelete`/`canUploadPhoto`(관리자면 항상 true, 게스트면
설정값을 따름)로 통일했다 — 표 입력칸은 `disabled` prop을, 여러 필드가 몰린 구역(그 밖의 유해위험정보 등)은
`<fieldset disabled>`로 한 번에 잠근다. **서버 쪽 검사가 진짜 방어선이고, 프런트 비활성화는 UX일 뿐이다.**

> 이전에는 Cloudflare Access(Zero Trust)로 앞단을 막는 방식을 썼다. Access와 자체 로그인 화면은
> 함께 못 쓴다 — Access가 우리 로그인 페이지보다 먼저 요청을 가로채 버린다. 지금은 Access를
> 완전히 제거하고 이 방식으로 바꿨다.

## 사이드바 접기·펼치기

SSM처럼 헤더 왼쪽 토글로 데스크톱 사이드바를 접었다 펼 수 있다(`src/components/shell.tsx`). 접으면
인트라넷 셸의 offcanvas 방식 그대로 폭이 0으로 줄고 패널이 화면 밖으로 슬라이드한다(`left: calc(var(--sidebar-width) * -1)`).
상태는 `localStorage("ras.sidebarOpen")`에 저장돼 새로고침해도 유지된다. 모바일은 기존 오버레이 시트를 그대로 쓴다.

## 차트

라이브러리 없이 HTML/SVG로 그린다(`src/components/charts.tsx`). 히트맵·막대 모두 단일 계열이라
`--series-1` 한 색만 쓴다(2계열 비교였던 개선 전후 막대는 삭제됨 — 대시보드 참고).
흰 배경 대비 3:1 이상으로 검증했다(dataviz 검증 스크립트). 축은 하나만 쓰고 이중 축은 만들지 않는다.

## 엑셀 가져오기

두 곳에서 불러올 수 있다.
- **목록 화면**: 파일 하나를 새 평가표로 만든다(대상시설·공정명·평가일시까지 읽음)
- **평가표 상세**: 열려 있는 평가표에 행만 불러온다 — 아래에 추가 / 기존 행 교체를 고른다

컬럼 위치를 고정으로 읽지 않고 **머리말 이름으로 찾는다**(`detectLayout`). 원본 서식(머리말 4~5행)과
이 앱이 내보낸 파일(머리말 2행)을 모두 처리하며, `현재 위험성`+`가능성`처럼 두 줄로 나뉜 머리말은
위·아래 칸을 붙여서 판별한다. 가능성·중대성은 나오는 순서대로 첫 벌이 개선 전, 둘째 벌이 개선 후다.

## 유지보수 메모

- 고위험군 기준점을 바꾸면 고위험군 목록은 즉시 다시 계산되지만, 이미 부여된 **평가코드는 해당 평가표를 열어 수정할 때** 다시 매겨진다.
- `/api/backup`은 사진을 base64로 바꿀 때 `toBase64()`(`worker/index.ts`)로 32KB씩 나눠 이어붙인다.
  `String.fromCharCode(...전체배열)`을 한 번에 쓰면 사진이 몇십 KB만 넘어도 인자 개수 한도를 넘겨 500이 난다
  (실제로 겪은 버그) — 사진 관련 서버 코드를 고칠 때 이 패턴을 다시 쓰지 않도록 주의.

## 디자인

인트라넷 디자인 시스템 정본 토큰·클래스를 그대로 이식(`src/index.css`, `src/components/ui.tsx`).
색은 전부 토큰이며 하드코딩 색은 인쇄 서식(`.sheet`)에만 있다 — 관공서 제출 서식이라 흑백 고정이 필요하다.
